# Figma Design System Auditor — паспорт проекта

## Что это

Плагин Figma, который сам находит проблемы в файле и сам приводит дизайнера к месту проблемы. Две оси ценности:

1. **Поиск проблем** — полный аудит слоёв, компонентов, переменных, структуры, контента и a11y.
2. **Решение проблем** — навигация к ноде в один клик, массовые автофиксы с превью, откат массового действия одной кнопкой, ignore-лист.

Ключевое отличие от обычного поиска в Figma: там пользователь знает, что ищет, и как оно называется. Здесь плагин находит сам и ведёт сам.

## Позиционирование

Рынок линтеров хардкода (Design Lint и аналоги) насыщен. Дифференциация проекта не в списке ошибок, а в трёх вещах, которых нет ни у кого:

- **Impact analysis** — «что сломается, если удалить этот токен / переименовать компонент / схлопнуть варианты», до рефакторинга.
- **Adoption-тренд** — снапшоты состояния файла во времени: % покрытия токенами, доля detached-инстансов, здоровье по категориям. Разовый скан — инструмент, тренд — продукт.
- **Layer-aware правила токенов** — не «переменная есть / переменной нет», а проверка соблюдения слоёв дизайн-системы (компонент забиндился к примитиву `gray-500` вместо семантики `text-secondary` — формально зелёно, фактически система сломана).

## Tech stack

| Слой | Технология |
|---|---|
| Plugin sandbox | TypeScript, Figma Plugin API (`figma.*`) |
| UI (iframe) | React 18 + TypeScript + Vite |
| Стили | Tailwind CSS v3 |
| Компоненты | Shadcn UI (адаптированные под плотность Figma-панели) |
| Сборка | Vite + `vite-plugin-singlefile` для UI, esbuild для `code.ts` |
| Тесты правил | Vitest на моках нод |

Целевой размер UI-бандла — до 500 KB. Figma iframe не любит тяжёлые бандлы.

### Правило = чистая функция

```ts
type Rule = {
  id: string;                    // 'tokens/raw-fill'
  category: RuleCategory;
  defaultSeverity: Severity;     // 'error' | 'warning' | 'info'
  scope: NodeScope[];            // какие типы нод интересуют
  check: (node: SceneNode, ctx: RuleContext) => Issue[];
  fix?: (issue: Issue, ctx: RuleContext) => FixAction[];
};
```

`RuleContext` содержит предпостроенный индекс: переменные по id, коллекции с уровнями, компоненты, мастера, карта instance→main, граф алиасов. Правило **никогда** не ходит по дереву само и не делает `async` вызовов внутри `check`.

### Скан двухфазный

Синхронность `check` возможна только потому, что весь async сделан до него. `getLocalVariablesAsync` отдаёт **только локальные** переменные; библиотечная достаётся лишь `getVariableByIdAsync(id)` — по одному id и асинхронно, а список нужных id известен только после обхода дерева. Отсюда жёсткий порядок:

```
1. VariableResolver.build()   локальные переменные и коллекции
2. traverse()                 обход, сбор bound variable ids
3. resolver.hydrate(ids)      догрузка библиотечных
4. прогон правил              полностью синхронный
```

Гидрацию нельзя сдвинуть до обхода — см. [решение 0004](docs/decisions/0004-variable-resolver.md).

Добавление правила = один файл + регистрация. Ядро не трогается.

## Каталог правил

### Токены и переменные (`tokens/`)
- `raw-fill`, `raw-stroke`, `raw-text-color` — цвет вне переменной
- `raw-spacing`, `raw-radius` — числовое значение вне шкалы
- `broken-alias` — биндинг на удалённую переменную
- `missing-mode-value` — значение пропущено в одном из режимов (тихо падает в fallback, всплывает только в dark)
- `layer-violation` — компонент биндится к примитиву вместо семантики ⭐
- `orphan-variable` — переменная не используется нигде
- `alias-depth` / `alias-cycle` — глубина цепочки и циклы
- `off-scale-value` — значение близко к токену, но не равно (кандидат на фикс)

### Компоненты (`components/`)
- `detached-instance` — эвристика по структурному совпадению с мастером
- `breaking-override` — оверрайд не контента, а цвета/отступа/шрифта
- `outdated-instance` — не обновлён после апдейта библиотеки
- `near-duplicate-component` — кандидаты на слияние
- `incomplete-variant-matrix` — пропущенные комбинации пропов
- `deprecated-usage` — использование компонента, помеченного deprecated

### Структура (`structure/`)
- `absolute-position` — там, где должен быть auto-layout
- `group-instead-of-frame`
- `default-name` — `Frame 427`, `Rectangle 12`
- `hidden-layer`, `zero-opacity` — забытые в проде
- `exact-duplicate` — дубликаты друг на друге
- `orphan-node` — нода вне фрейма на канвасе

### Контент и хендофф (`content/`)
- `placeholder-text` — lorem ipsum, `asdf`, `TODO`
- `truncated-text`
- `broken-prototype-link`
- `unreachable-frame` — фрейм без входящих переходов
- `missing-font`

### Доступность (`a11y/`)
- `token-pair-contrast` — контраст **пар токенов**, не пикселей. Проверка один раз на систему, а не на каждый слой.
- `touch-target-size`

## Критические ограничения

### Производительность
На файле в 150k нод наивный обход блокирует UI, и плагин закрывают, не дождавшись. Обязательно:

- **Один обход** со сборкой индекса. Дальше все правила работают по индексу, дерево не обходится повторно. Обход итеративный, на явном стеке: глубина вложенности во фрейме не ограничена, а стек вызовов JS ограничен.
- Чанкинг обхода с `await new Promise(r => setTimeout(r, 0))` каждые ~500 нод.
- Прогресс-бар с кнопкой отмены. Для full-file скана прогресс **двухуровневый**: страницы и ноды. Отмена возвращает частичный результат, а не исключение.
- Страницы грузятся **лениво, по одной**, а не через `loadAllPagesAsync`: отмена на третьей странице из сорока не должна быть оплачена загрузкой сорока.
- Инкрементальный ре-скан — по событиям `nodechange`, не по хэшу ноды: поля версии у `SceneNode` нет. **Кэш живёт только внутри сессии**, первый скан после открытия плагина всегда полный. См. [решение 0003](docs/decisions/0003-incremental-invalidation.md).
- **Скоуп по умолчанию — выделение или страница**, не весь файл. Full-file скан — явное действие. Под dynamic-page у этого дефолта есть вторая причина: скан текущей страницы не грузит остальные.

### Figma API
- Манифест объявляет `documentAccess: "dynamic-page"`. Следствия: `figma.root.findAll()` требует `loadAllPagesAsync()`, `page.findAll()` — `page.loadAsync()`, а синхронный `getNodeById` **бросает исключение**. Все синхронные аналоги запрещены правилом ESLint в `src/main/**` — нарушение не проходит линт. См. [решение 0002](docs/decisions/0002-dynamic-page-traversal.md).
- Библиотечные переменные не видны полностью без импорта. `figma.teamLibrary.*` асинхронный и урезанный. Модель — **три состояния**: `local` / `library` / `unavailable`. Третье означает «плагин не смог достать», а не «удалена»; отличить их невозможно, поэтому правила про `unavailable` **молчат** по умолчанию. Правило спрашивает `resolver.canJudge(id)`, а не проверяет `null` само.
- `getLocalVariableCollectionsAsync` и родственные — все async. **Локальный** индекс переменных строится до обхода дерева, библиотечный достраивается после (см. «Скан двухфазный»).
- Цвета в API — `{r,g,b,a}` в диапазоне 0–1. Конвертация в hex/OKLCH только в UI-слое.
- Абсолютная позиция — через `absoluteTransform`, не через `x`/`y`.
- `setPluginData` лимит ~100 KB на ноду; ignore-флаг хранить максимально коротко.

### Доверие к автофиксам
Первый же неудачный массовый автофикс на боевом файле хоронит доверие к плагину навсегда. Поэтому:

- Превью-дифф до применения — всегда, без опции «применить сразу».
- Откат массового действия — **собственный, не нативный**. Транзакционного API у Figma нет, а чанкинг через yield разрывает батч истории, поэтому Cmd+Z откатил бы случайную часть. Каждый фикс обязан записать `previousValue`; в UI — явная кнопка «Отменить последнее массовое действие». Нативный Cmd+Z остаётся неопределённым, и это надо проговорить в интерфейсе. См. [решение 0001](docs/decisions/0001-undo-strategy.md).
- Ignore-лист на уровне ноды через `setPluginData` («это намеренно»). Без него любой линтер за неделю превращается в шум, который отключают.

## Конфигурация

ESLint-подобный JSON, живёт в `figma.root.setPluginData('audit-config')`, экспортируется/импортируется файлом. Команда шарит один конфиг; у DS-мейнтейнера и продуктового дизайнера — разные пресеты.

```json
{
  "version": 1,
  "extends": "recommended",
  "scope": { "default": "page" },
  "rules": {
    "tokens/raw-fill": "error",
    "tokens/layer-violation": "error",
    "structure/default-name": "off",
    "a11y/token-pair-contrast": ["warning", { "level": "AA" }]
  },
  "tokenLayers": {
    "primitives": ["Primitives", "Palette"],
    "semantic": ["Semantic", "Theme"],
    "component": ["Component"]
  }
}
```

`tokenLayers` — обязательное поле для работы `layer-violation`. Без него правило отключается, а не гадает.

## Roadmap

**MVP (релиз 1).** Токены + компоненты, ~10 правил, идеальная навигация по клику (select + zoom + подсветка), массовый фикс с превью, ignore-лист, конфиг. Скоуп — страница. Это уже используемо.

**Релиз 2 — Impact analysis.** Обратный граф: токен → потребители, компонент → инстансы, вариант → использования. Это причина, по которой плагин выберут вместо Design Lint.

**Релиз 3 — Adoption.** Снапшоты в `documentPluginData`, тренд по времени, экспорт отчёта. То, что показывают руководству и что оправдывает существование дизайн-системы.

**Релиз 4.** Структура, контент, a11y. Usage analytics по библиотеке — какие компоненты и варианты никто не берёт за полгода.

## Валидация до кода

Перед реализацией: взять боевой файл, прогнать вручную 5 предполагаемых правил, посчитать долю реальных проблем против ложных срабатываний. **Если сигнал ниже 70% — продукт мёртв независимо от качества реализации.** Правило с плохим сигналом либо переписывается, либо уходит в `info`, либо выкидывается.

## Соглашения по коду

- TypeScript strict. `any` запрещён, для Figma-типов — narrowing через type guards.
- Сообщения main↔ui — дискриминированные юнионы в `shared/messages.ts`, никаких строковых литералов в вызовах.
- Правила покрываются юнит-тестами на моках нод. Новое правило без теста не мержится.
- В `main/` нет React, в `ui/` нет `figma.*`.
- Никаких синхронных тяжёлых циклов в `main/index.ts` — только через `scanner/traversal.ts`.
- Именование правил — `category/kebab-case`, совпадает с путём файла.
- Архитектурные решения, разошедшиеся с первой редакцией этого паспорта, живут в `docs/decisions/`. Текст выше уже приведён к ним; при следующем расхождении правится паспорт, а не память читателя.

## Definition of Done для правила

1. Чистая функция, ноль обращений к дереву.
2. Юнит-тест: позитивный кейс, негативный, граничный.
3. Сообщение об ошибке объясняет **что не так и почему**, а не только факт.
4. Если есть `fix` — есть превью-дифф и проверка идемпотентности.
5. Прогон на боевом файле, сигнал ≥ 70%.
6. Если правило читает переменные — состояние `unavailable` обработано через `resolver.canJudge(id)`, и на нём правило молчит. Тест на это состояние обязателен: на боевых файлах оно самое частое и самое забываемое.
