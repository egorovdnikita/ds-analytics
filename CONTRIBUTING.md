# Как контрибьютить

## Быстрый старт

```
npm ci
npm run verify     # typecheck + lint + test + build
npm run dev        # watch-сборка plugin sandbox
```

Импорт плагина в Figma: **Plugins → Development → Import plugin from manifest** → выбрать `manifest.json` из корня репозитория. Перед первым импортом выполнить `npm run build` — манифест ссылается на `dist/`.

> `manifest.json` намеренно без поля `id`. Для локальной разработки оно не нужно; Figma присваивает id при создании плагина в Community. Не коммитить чужой id.

## Структура

| Путь            | Что можно                       | Чего нельзя                      |
| --------------- | ------------------------------- | -------------------------------- |
| `src/main/**`   | Figma API, чистая логика правил | React, DOM, синхронные Figma-API |
| `src/ui/**`     | React, DOM                      | `figma.*`, импорты из `main/`    |
| `src/shared/**` | Типы и контракты                | И то и другое                    |

Границы держит не договорённость, а линтер и раздельные `tsconfig`. Попытка нарушить падает в `npm run lint`.

## Как добавить правило

1. Один файл в `src/main/rules/<category>/<kebab-case>.ts`, экспортирующий объект `Rule`.
2. Регистрация в `src/main/rules/registry.ts`. Ядро не трогается.
3. Тест в `test/rules/<category>/<kebab-case>.test.ts`: позитивный, негативный, граничный кейс.
4. Моки нод — из `test/factories/node.ts`. Не писать моки руками.
5. Есть `fix` — есть проверка `expectIdempotent` из `test/factories/idempotency.ts`.

`check` — **чистая функция**. Она не ходит по дереву и не делает `async`-вызовов: всё, что нужно, лежит в предпостроенном `RuleContext`. Обход дерева — только в `scanner/traversal.ts`.

### Сообщение об ошибке

Формулировка обязана объяснять **почему это проблема**, а не констатировать факт.

- ✗ `Цвет не из переменной`
- ✓ `Заливка задана напрямую (#3B82F6). При смене темы этот слой не переключится — он не привязан к переменной.`

Правило, для которого не формулируется внятное «почему», — кандидат на выброс, а не на реализацию.

## Фиксы и откат

Плагин **не полагается на нативный Cmd+Z** — см. [решение 0001](docs/decisions/0001-undo-strategy.md). Практические следствия для автора правила:

- `fix` обязан прочитать текущее значение свойства **до** записи и положить его в `FixAction.previousValue`. Поле не опциональное.
- Одно `FixAction` = одно свойство одной ноды. Фикс, меняющий три свойства, возвращает три действия.
- Записывать действия в `UndoJournal` (`src/main/fixes/journal.ts`) — задача applier'а, не правила.

## Открытые архитектурные решения

Перед работой над `scanner/` прочитать [docs/pre-launch-audit.md](docs/pre-launch-audit.md), блоки B2–B4: инкрементальный кэш, dynamic-page обход и библиотечные переменные пока не имеют принятых решений. Код, написанный до них, придётся переписывать.

Принятые решения живут в [docs/decisions/](docs/decisions/).
