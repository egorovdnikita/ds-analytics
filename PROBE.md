# Пробник сигнала — ветка `spike/signal-probe`

> **Эта ветка не мержится в `main`.** Здесь измерительный инструмент, а не продукт.
> Из неё переносятся цифры, а не код.

Собран по [протоколу валидации](docs/validation/protocol.md), шаг 3.

## Зачем

Гейт паспорта: правило с сигналом ниже 70% в продукт не идёт. Судить срабатывания вручную по боевому файлу невозможно — пробник находит кандидатов и выдаёт готовую к судейству таблицу.

## Как прогнать

**Нужно десктопное приложение Figma** — в браузере локальные плагины не запускаются.

```bash
git checkout spike/signal-probe
npm ci && npm run build
```

Затем в Figma: **Plugins → Development → Import plugin from manifest…** → `manifest.json` из корня. Запуск — **Plugins → Development → Design System Auditor**.

Если Figma потребует поле `id` в манифесте — см. раздел «Про поле `id`» в [CONTRIBUTING.md](CONTRIBUTING.md).

1. Открыть боевой файл.
2. Выбрать скоуп. Начинать со **страницы**: на весь файл имеет смысл идти, только когда понятен порядок величин.
3. Прогнать. Кнопка отмены работает — отменённый прогон помечается в шапке CSV как неполный.
4. Скопировать CSV в таблицу, заполнить колонку «вердикт» по рубрике протокола.
5. Итоги — в [docs/validation/results.md](docs/validation/results.md), в `main`.

## Перед прогоном на конкретном файле

Разметка слоёв правится руками в константе `TOKEN_LAYERS` в [src/main/index.ts](src/main/index.ts). Пробник намеренно без настроек.

**Если имена коллекций файла не ложатся в эти списки — это уже результат замера,** а не повод подгонять константу: значит `tokens/layer-violation` неприменимо из коробки и MVP нужен мастер разметки слоёв при первом запуске. Записать в results.md, в отдельный блок.

## Что показывает экран результата

Не список счётчиков, а ответ на вопрос «что это число значит». Три исхода различаются явно:

| Исход            | Значит                                                                    |
| ---------------- | ------------------------------------------------------------------------- |
| **N · судить K** | Правило отработало и нашло N. Судить предстоит K из выборки               |
| **чисто**        | Правило отработало и не нашло ничего. Рядом — почему это осмысленный ноль |
| **не применимо** | Правило не могло отработать в принципе. Рядом — причина                   |

Третий случай в голом списке счётчиков читается как «у меня всё хорошо», хотя означает «инструмент здесь слеп». **Именно на этом смешении мы потеряли два прогона.**

Кроме правил экран показывает профиль файла (источник библиотеки / потребитель / без ДС), ключевые счётчики, имена коллекций переменных и вердикт по разметке слоёв. CSV убран под кнопку — он для выгрузки, а не для чтения.

## Что внутри

| Файл                       | Что делает                                         |
| -------------------------- | -------------------------------------------------- |
| `src/main/probe/checks.ts` | Пять проверок. Эвристики намеренно примитивные     |
| `src/main/probe/sample.ts` | Seeded-выборка по 30 на правило                    |
| `src/main/probe/report.ts` | CSV с пустой колонкой «вердикт»                    |
| `src/main/index.ts`        | Входная точка: обход → гидрация → прогон → выборка |

Обход и индекс переменных — **боевые** `scanner/traversal.ts` и `scanner/variables.ts`. Иначе меряется не то, что поедет в продукт.

## Почему seed

Выборка воспроизводима: тот же файл и тот же seed дают ту же выборку. Спор о цифре разрешается пересчётом, а не памятью. Seed записывается в шапку CSV — не терять его.

## Чего здесь нет и не будет

Фиксов, ignore-листа, настроек, конфига, навигации по клику, полировки UI. Всё это — продукт, и оно пишется после того, как гейт пройден.

## Что показал первый боевой прогон (2026-08-23)

Страница на 25804 ноды: `raw-fill` 5798, `default-name` 388, **остальные три — ноль**. Нули оказались дефектами инструмента, а не чистотой файла:

| Что было                                               | Почему                                                                                                   | Исправлено                                                                     |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `raw-fill` считал хардкодом заливку от **paint-стиля** | Проверялись только переменные. Файл собран на стилях, а не на переменных — отсюда тысячи ложных          | Проверяется `fillStyleId`                                                      |
| `raw-fill` срабатывал **внутри инстансов**             | Содержимое инстанса приходит из мастера, чинить его на месте нечем                                       | Ноды внутри инстансов пропускаются                                             |
| `detached-instance` не мог сработать **никогда**       | Имена мастеров брались только из локальных `COMPONENT`, а в файле-потребителе мастера лежат в библиотеке | Мастера резолвятся через `getMainComponentAsync` для инстансов верхнего уровня |
| Ноль было невозможно интерпретировать                  | Нет данных о том, есть ли в файле переменные и мастера вообще                                            | Добавлена диагностика в шапку CSV                                              |

**Цифру 5798 из первого прогона использовать нельзя** — она получена сломанным инструментом. Прогонять заново.

### Диагностика в шапке

Теперь CSV начинается со счётчиков: сколько нод внутри инстансов, сколько с биндингом переменной, сколько со стилем заливки, сколько локальных коллекций и **как они называются**. Плюс явные выводы вида «переменные в скоупе не используются — layer-violation здесь неприменим».

Имена коллекций отвечают на вопрос шага A2 протокола напрямую: если они выглядят как `Colors`, `Colors 2`, `New colors final`, то `layer-violation` неприменимо из коробки, и это результат замера, а не повод подгонять `TOKEN_LAYERS`.

## Второй прогон (2026-08-23)

После исправлений: `raw-fill` **5798 → 38**, `detached-instance` **0 → 9**, `default-name` 388 без изменений. Диагностика показала главное: **9220 нод с биндингом переменной при нуле локальных коллекций** — файл целиком на библиотечных переменных.

Отсюда третья правка, уже в продуктовом коде: `VariableResolver` не догружал коллекции библиотечных переменных, поэтому слой у всех 9220 биндингов был `null` и `layer-violation` **молча не работало**. По нулю в отчёте это неотличимо от «нарушений нет». Исправлено в `main` ([решение 0004](docs/decisions/0004-variable-resolver.md)).

Заодно замер снял опасение паспорта: состояние `unavailable` не встретилось **ни разу** — библиотечные переменные резолвятся штатно.

## Оговорка по `broken-alias`

Пробник **не утверждает**, что переменная удалена. Отличить «удалена» от «недоступна плагину» невозможно ([решение 0004](docs/decisions/0004-variable-resolver.md)) — он показывает кандидатов, а дизайнер проверяет в Figma.

Доля реально удалённых среди них и есть искомая цифра. Если она низкая, правило `broken-alias` в текущем виде не нужно: оно ловит ограничение инструмента, а не проблему файла.
