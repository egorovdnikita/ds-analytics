# 0001. Откат массового фикса — собственный, не нативный

**Статус:** принято, 2026-08-23
**Контекст:** [pre-launch аудит, блок B1](../pre-launch-audit.md)

## Проблема

Паспорт проекта обещает две вещи, которые конфликтуют:

1. «Все изменения одного bulk-действия — одна отменяемая транзакция».
2. «Чанкинг обхода с `await new Promise(r => setTimeout(r, 0))` каждые ~500 нод».

В Figma Plugin API нет транзакционного API — нет `beginTransaction` / `commit`. Группировка правок в один шаг истории является побочным эффектом того, как Figma батчит изменения плагина, и yield между правками с высокой вероятностью разрывает батч.

Цена ошибки задана самим паспортом: «Первый же неудачный массовый автофикс на боевом файле хоронит доверие к плагину навсегда». Пользователь, применивший 200 фиксов и нажавший Cmd+Z, не должен получить откат двенадцати.

## Решение

**Плагин откатывает свои изменения сам.**

- Перед каждым изменением свойства фикс обязан записать `previousValue` в `FixAction`. Поле не опциональное: фикс, который не может назвать предыдущее значение, не применяется.
- `main/fixes/journal.ts` — `UndoJournal`: копит записи и откатывает их **в обратном порядке**. Обратный порядок обязателен, потому что два фикса могли тронуть одно свойство одной ноды.
- В UI плагина — явная кнопка «Отменить последнее массовое действие», не полагающаяся на Cmd+Z.
- Удалённая или недоступная нода при откате — **пропуск, не ошибка**. Один удалённый слой не должен блокировать откат остальных.
- Журнал не резолвит ноды сам: резолвер передаётся снаружи, потому что при `documentAccess: "dynamic-page"` доступ асинхронный и зависит от загрузки страницы.

## Что мы теряем

Нативный Cmd+Z остаётся неопределённым: он откатит какую-то часть изменений. Это приемлемо, потому что гарантия даётся кнопкой в плагине, а не системной историей. Но **в UI это надо проговорить текстом** — иначе пользователь применит Cmd+Z, получит частичный откат и решит, что плагин сломан.

Открытый вопрос для UI: показывать ли подсказку «используйте кнопку отмены в плагине» сразу после применения массового фикса. Скорее да.

## Отвергнутые варианты

**Синхронный батч без yield.** Уложиться в один нативный шаг истории, ограничив размер батча. Отвергнут: упирается во фриз UI ровно на тех файлах, ради которых проект существует, и вынуждает показывать «будет применено 500 из 2000».

**Комбинация свой откат + попытка уложиться в нативный шаг.** Отвергнут на текущем этапе как самый дорогой при том же результате для пользователя. Вернуться, если появятся жалобы на неожиданное поведение Cmd+Z.

## Последствия

- `FixAction` получил обязательные `property`, `previousValue`, `nextValue`.
- Каждое правило с `fix` обязано уметь читать текущее значение свойства до записи.
- `previousValue` типизирован как `unknown`: журнал не интерпретирует значение, а возвращает его как есть.
