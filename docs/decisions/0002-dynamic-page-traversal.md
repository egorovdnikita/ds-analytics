# 0002. Обход дерева при documentAccess: "dynamic-page"

**Статус:** принято, 2026-08-23
**Контекст:** [pre-launch аудит, блок B3](../pre-launch-audit.md)

## Проблема

Паспорт описывает `indexer.ts` как «один `findAll()` → NodeIndex». При `documentAccess: "dynamic-page"` это неверно.

Проверено по `@figma/plugin-typings` (версия в `package-lock.json`):

- `figma.root.findAll()` требует предварительного `figma.loadAllPagesAsync()`.
- `page.findAll()` требует предварительного `page.loadAsync()` для страницы, отличной от текущей.
- Синхронный `figma.getNodeById` под dynamic-page **бросает исключение**, а не возвращает `null`.

То есть «один `findAll()`» существует только для скана одной уже загруженной страницы. Full-file скан — это N загрузок страниц, каждая из которых стоит времени.

## Решение

**Два уровня прогресса, ленивая загрузка страниц, отмена между чанками.**

- `ScanTarget` — дискриминированный юнион `selection` / `page` / `file`. Скоуп перестаёт быть строкой и становится тем, что определяет стратегию загрузки.
- `file` загружает страницы **по одной, лениво**, а не через `figma.loadAllPagesAsync()`. Пользователь видит «страница 3 из 40» и может отменить, не дождавшись загрузки всех сорока.
- Обход **итеративный, на явном стеке**, не рекурсивный: глубина вложенности во фрейме не ограничена, а стек вызовов JS ограничен.
- `yield` каждые `chunkSize` нод (по умолчанию 500) — значение из паспорта.
- Отмена проверяется на границе чанка и на границе страницы. Отменённый обход возвращает **частичный результат с флагом `cancelled`**, а не бросает исключение: половина индекса лучше, чем ничего, и UI сам решает, что с ней делать.
- Функция `yieldToEventLoop` инжектируется параметром — иначе тесты либо ждут реального таймера, либо не проверяют чанкинг вовсе.

## Дефолтный скоуп — не UX-предпочтение, а архитектура

Паспорт объявляет дефолтным скоупом страницу. Под dynamic-page у этого появляется вторая причина: скан текущей страницы **не грузит остальные**, то есть дефолт не просто «быстрее», а качественно дешевле. Full-file остаётся явным действием пользователя.

## Последствия

- Любое обращение к ноде по id — только `figma.getNodeByIdAsync`. Синхронные варианты запрещены правилом ESLint `no-restricted-syntax` в `src/main/**` — нарушение не проходит линт.
- `Issue` хранит `pageId` рядом с `nodeId`: чтобы показать ноду, нужно сперва загрузить и переключить её страницу.
- Индекс, построенный по скоупу `page`, **не содержит данных о других страницах**. Правила, которым нужен весь файл (`orphan-variable`, `near-duplicate-component`), обязаны объявлять это требование и отключаться вне скоупа `file`. Механизм объявления — открытый вопрос, к нему вернуться при реализации реестра правил.
